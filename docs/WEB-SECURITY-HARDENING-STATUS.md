# Web security hardening — PR #382 status

Scope: web application and Spring Boot API only. Native iOS is explicitly excluded.

## Implemented on this branch

- **Same-origin API proxy:** Vercel rewrites `/api/v1/*` to the Render API before the SPA fallback. Production and development browser code use `/api/v1`; Vite proxies that path to `http://localhost:8080` (or `VITE_DEV_API_PROXY_TARGET`) locally. `mountPortal` installs the same secure fetch transport for every standalone role portal, not just the combined root app.
- **Cookie authentication:** the browser receives a `__Host-ku_session` cookie with Secure, HttpOnly, SameSite=Lax and Path=/ attributes after OTP verification, portal handoff redemption, and legacy bearer-session validation. Logout revokes the server session and clears the cookie. Cookie sessions take precedence over Authorization headers at the filter boundary so existing controller/service contracts remain compatible.
- **CSRF:** same-origin browser mutations require an allowlisted Origin plus a constant-time double-submit `__Host-ku_csrf` / `X-KU-CSRF` match. The browser transport bootstraps the CSRF cookie before unsafe API calls. Non-browser bearer integrations without cookies remain compatible.
- **Browser token storage:** successful OTP and legacy-session bootstrap replaces the stored bearer value with a non-secret marker. The shared fetch transport removes Authorization headers after cookie upgrade. Legacy raw bearer values are accepted only for the first session restoration request so existing users can be upgraded without a forced logout.
- **Session token hashing:** application-issued session tokens are SHA-256 hashed before persistence. AuthService lookups, active-role lookups, logout, delivery tracking and portal handoff use the same digest. Portal handoff rows store the source session digest, not the raw credential.
- **Oracle migration:** V43 converts existing `USER_SESSIONS.SESSION_TOKEN` and `AUTH_PORTAL_HANDOFFS.SESSION_TOKEN` values to lowercase SHA-256 hex in place, preserving valid existing browser tokens because lookups hash the presented token before querying. Migration has not been run against staging or production from this session.
- **Session lifetime:** first-party browser sessions use a 30-minute sliding idle expiry and 12-hour absolute expiry. Browser transport rotates the opaque token every 15 minutes of active API use; in-tab single-flight and cross-tab Web Locks/localStorage coordination reduce races, and Oracle compare-and-update rejects concurrent/replayed rotation. Non-browser bearer clients retain their 12-hour absolute expiry. Portal handoff sessions cannot outlive their source.
- **Security headers:** HSTS, no-store cache controls, strict referrer policy, CSP report-only and Permissions-Policy are configured. CSP remains report-only pending a real asset/report review.
- **Automation and dependency remediation:** CodeQL covers Java and JavaScript/TypeScript. Trivy scans Maven and Bun dependency manifests/lockfiles without relying on GitHub Dependency Graph. Its first scan identified a high-severity Vite advisory; Vite and the Bun lockfile were upgraded from 8.3.2 to patched 8.3.3. On commit `74357f0`, CodeQL, Trivy and the backend Docker security gate passed. The ZAP baseline ran against the configured HTTPS `STAGING_BASE_URL`: 57 passive checks passed, 11 warnings were reported, and no new failures were reported. The action is configured `fail_action: false`, so a successful job is not a clean-scan certification.
- **OTP abuse throttling:** OTP send is limited to 5 requests per identifier per hour; OTP verification is limited to 20 per identifier per hour, in addition to the existing cooldown and five-attempt OTP consumption rules. The browser transport adds a random UUIDv4 device key; device limits are 10 sends and 30 verifications per hour. Device keys are treated as untrusted abuse-friction signals, and only their SHA-256-derived rate-limit bucket is persisted.
- **Trusted client IP handling:** `TrustedClientIpResolver` ignores forwarded headers unless the immediate peer is in the explicitly configured `ku.security.trusted-proxy-cidrs` CIDR list. When configured, it walks the forwarding chain from the trusted edge inward and selects the first untrusted hop. Until the actual Render ingress/Vercel proxy chain is verified and `KU_SECURITY_TRUSTED_PROXY_CIDRS` is configured, IP-based OTP buckets are intentionally not activated; arbitrary `X-Forwarded-For` is never trusted.
- **Session lifecycle:** V46 adds an immutable absolute expiry. Browser sessions have a 30-minute sliding idle expiry and a 12-hour absolute lifetime. The browser performs single-flight opaque-token rotation every 15 minutes of active API use; Oracle compare-and-update prevents concurrent/replayed refreshes from rotating the same token twice. Existing active sessions receive up to 30 minutes after migration before needing a fresh login.
- **Admin MFA:** admin API access now requires TOTP step-up after the ADMIN role check. TOTP secrets are AES-GCM encrypted with a domain-separated key derived from the existing `JWT_SECRET`; 10 one-time recovery codes are stored as hashes; the step-up cookie is HttpOnly, Secure, host-only and expires after 10 minutes. Step-up is bound to the active session digest, and a database counter prevents TOTP replay. The admin portal includes setup, confirmation, recovery-code display and challenge screens. Do not rotate `JWT_SECRET` without a planned admin MFA re-enrollment/key-rotation procedure.
- **Admin mutation audit:** V44 adds an append-only `SECURITY_AUDIT_EVENTS` table. A web interceptor records successful and failed admin mutations with actor, action, target, HTTP status and redacted handler metadata; request bodies and credentials are never stored. Failed mutation/audit-write conditions are also emitted as structured application logs. External alert routing is not configured here.
- **Admin response DTOs:** seller and delivery-fleet list/detail mutation responses now use explicit admin DTOs. Internal seller agreement IP and E2E run metadata are excluded from the response contract.
- **Regression tests:** added cookie-session filter tests, CSRF allow/deny tests, token-hash tests, portal handoff digest assertions, trusted-proxy spoofing tests, OTP device/IP limiter tests, TOTP/recovery/replay tests, admin audit/DTO tests and Vercel/Vite same-origin proxy contract tests. Browser local login/handoff tests were updated to use cookies. The registration flow was corrected to accept first-party cookie login responses that intentionally omit a JavaScript bearer token.

## Remaining controls before security programme completion

1. **Trusted-proxy IP activation:** identifier and device OTP limits are implemented. The IP limiter is implemented but deliberately inactive until the actual Vercel-to-Render immediate-peer chain is verified and `KU_SECURITY_TRUSTED_PROXY_CIDRS` is configured with exact CIDRs. Do not use `0.0.0.0/0`, guess ranges, or trust arbitrary forwarded headers.
2. **Complete IDOR/ownership matrix:** inventory every protected read/write across buyer, seller, delivery, Daily Help, documents, negotiations, tracking and admin; add owner-positive and wrong-owner/wrong-role negative tests for every endpoint. Existing route-role gates and selected ownership tests are not a complete audit.
3. **Admin MFA operations:** TOTP enrollment, session-bound 10-minute step-up, recovery codes and replay prevention are implemented. Before enabling in the deployed environment, rehearse V45 on isolated staging Oracle and verify the admin authenticator enrollment/recovery journey. A lost-authenticator-and-lost-recovery-codes break-glass procedure must be documented and access-controlled.
4. **Idle timeout and refresh rotation:** implementation and automated regression coverage exist (30-minute idle expiry, 12-hour absolute expiry, 15-minute active rotation and compare-and-update replay protection). Still required: rehearse the complete lifecycle on staging Oracle, including idle expiry, absolute expiry, cross-tab refresh, concurrent refresh and replay rejection.
5. **Explicit DTO inventory:** seller and delivery-fleet admin responses now use explicit DTOs. Continue the endpoint-wide audit and convert remaining entity responses, especially across admin, buyer, seller, delivery and Daily Help, without breaking portal contracts.
6. **Audit and alerts:** admin mutations now have append-only database audit events and structured failure logs. Extend coverage to sensitive admin reads, auth/session events and resource-denial events; define retention, access review and external alert routing. Never log bearer tokens, OTPs or document contents.
7. **CSP enforcement:** review real browser reports and third-party asset requirements, then remove unsafe directives and enforce CSP in a separately validated step.
8. **Authenticated DAST:** unauthenticated ZAP baseline completed on the configured staging target with 57 passes, 11 warnings and zero new failures. Triage the 11 warnings and run authenticated DAST with dedicated non-production identities; the baseline scan is not authenticated and is not a substitute.
9. **Operational validation:** verify Vercel rewrite, 30-minute idle refresh, absolute expiry and cookie behavior on every deployed portal hostname; configure and verify trusted proxy CIDRs; rehearse V43–V46 on isolated staging Oracle; complete all web role journeys and inspect CI on the final PR head before merge.
